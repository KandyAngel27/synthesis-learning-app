## Lesson Plan (24 Lessons)

### Unit 1: Computing Foundations (L1-5)
1. **"Digital Literacy & the Information Age"** — What is digital literacy: not just "using a computer" — the ability to find, evaluate, create, and communicate information using digital technologies (ALA definition). Five components of digital literacy: information literacy (finding and evaluating sources — CRAAP test: Currency, Relevance, Authority, Accuracy, Purpose), media literacy (understanding media messages, bias, misinformation vs disinformation), digital citizenship (responsible online behavior, netiquette, digital footprint, online identity), ICT proficiency (technical skills — hardware, software, troubleshooting), computational thinking (problem decomposition, pattern recognition, abstraction, algorithm design). The information age: agricultural age → industrial age → information age → data age (big data explosion — 2.5 quintillion bytes/day). Data vs information vs knowledge vs wisdom (DIKW pyramid): data = raw facts, information = processed data with context, knowledge = applied information, wisdom = experience-based judgment. Technology in healthcare: EHR systems, health informatics, telehealth, clinical decision support, health information exchange, population health analytics. Why HIM professionals need tech skills: managing electronic health records, data analytics, cybersecurity awareness, system implementation, interoperability, data governance
   - Cover: DIKW pyramid diagram, 5 components of digital literacy, information age timeline, CRAAP test evaluation framework

2. **"Computer Hardware: Inside the Machine"** — What is a computer: electronic device that processes data under the control of stored instructions. Four functions of every computer: input → processing → storage → output. Computer components: CPU (central processing unit — the "brain"), motherboard (main circuit board, bus system), RAM (random access memory — volatile, temporary workspace), ROM (read-only memory — firmware, BIOS/UEFI), storage devices (HDD — magnetic platters, SSD — flash memory/NAND, NVMe — fastest), GPU (graphics processing unit — parallel processing, also used for AI/ML). CPU deep dive: control unit (fetches and decodes instructions), ALU (arithmetic logic unit — performs calculations), registers (fastest storage, inside CPU), cache (L1/L2/L3 — faster than RAM, closer to CPU), clock speed (GHz — billions of cycles/second), cores (multi-core = parallel processing — dual, quad, octa), CPU manufacturers (Intel Core series, AMD Ryzen series). Machine cycle: fetch → decode → execute → store. Measuring data: bit (binary digit, 0 or 1), byte (8 bits), KB (1,024 bytes), MB, GB, TB, PB. Input devices: keyboard, mouse, touchscreen, scanner, microphone, webcam, barcode reader (used in healthcare — medication scanning, patient ID), biometric scanners (fingerprint, palm vein — patient identification). Output devices: monitor (LCD, LED, OLED, resolution — 1080p/4K/8K), printer (inkjet, laser, thermal — wristband printers in hospitals), speakers. Ports & connectivity: USB (A, B, C, Thunderbolt), HDMI, DisplayPort, Ethernet (RJ-45), audio jack, wireless (Bluetooth, Wi-Fi)
   - Cover: Computer architecture diagram (CPU/RAM/storage/I/O), CPU internal components, data measurement scale (bit → PB), port identification guide

3. **"Computer Hardware: Types & Form Factors"** — Desktop computers: tower, all-in-one (iMac style), workstations (high-performance for specialized tasks — medical imaging, 3D modeling). Laptop computers: portability, battery life, integrated display/keyboard/trackpad, ultrabooks (thin & light), mobile workstations. Tablets: touchscreen-primary, iPad/Android, used in healthcare (bedside charting, patient education, rounding). Smartphones: pocket computers, mobile OS (iOS, Android), healthcare apps (patient portals, clinical references, secure messaging). Servers: powerful computers that provide services to client computers, rack-mounted, blade servers, tower servers, data center environment (cooling, power redundancy, physical security). Mainframes: large-scale enterprise computing (banks, insurance companies, government — processing millions of transactions), IBM Z series. Supercomputers: extreme processing power (weather modeling, genomic research, drug discovery, AI training), measured in FLOPS (floating-point operations per second), top supercomputers (Frontier — exascale). Embedded systems / IoT devices: computers inside other devices (medical devices — infusion pumps, ventilators, patient monitors, pacemakers, insulin pumps), real-time operating systems. Wearable technology: smartwatches, fitness trackers, continuous glucose monitors, remote patient monitoring. Choosing the right computer: specifications for different use cases — basic office (i3/Ryzen 3, 8GB, 256GB SSD), business professional (i5/Ryzen 5, 16GB, 512GB), power user (i7/Ryzen 7, 32GB+, 1TB+), healthcare workstation (multiple monitors, HIPAA-compliant, medical-grade peripherals)
   - Cover: Computer type spectrum (smartphone → supercomputer), server rack anatomy, IoT medical devices grid, spec comparison table by use case

4. **"Operating Systems"** — What is an OS: system software that manages hardware resources, provides user interface, runs applications, manages files. OS functions: process management (multitasking — running multiple programs, scheduling, threads), memory management (allocating RAM, virtual memory — using disk as overflow RAM, paging), file system management (organizing data — NTFS for Windows, APFS for Mac, ext4 for Linux; files, folders, paths, permissions), device management (drivers — software that lets OS communicate with hardware, plug-and-play), security (user accounts, authentication, permissions, encryption, firewall). Desktop operating systems: Windows (Microsoft — dominant in business/healthcare, versions: Windows 10, Windows 11, Windows Server), macOS (Apple — Unix-based, popular in creative/education), Linux (open-source, distributions — Ubuntu, Red Hat, CentOS, Fedora; dominant in servers, IoT, supercomputers; command line — bash/terminal). Mobile operating systems: iOS (Apple — iPhone/iPad, App Store, closed ecosystem), Android (Google — open-source base, Play Store, manufacturer customization — Samsung One UI, Pixel). Server operating systems: Windows Server (Active Directory, Group Policy, enterprise management), Linux (Apache, nginx, most web servers run Linux), cloud OS instances (AWS Amazon Linux, Azure Windows Server). User interfaces: GUI (graphical user interface — windows, icons, menus, pointer = WIMP), CLI (command-line interface — PowerShell, Terminal, bash — more powerful but steeper learning curve), touch interface, voice interface (Siri, Alexa, Cortana). Virtualization: running multiple OSes on one physical machine, hypervisors (Type 1 — bare metal: VMware ESXi, Hyper-V; Type 2 — hosted: VirtualBox, VMware Workstation), VMs (virtual machines), containers (Docker — lightweight, share OS kernel). Healthcare OS considerations: Windows dominance in healthcare IT (EHR clients, PACS workstations), HIPAA compliance requirements (encryption, access controls, audit logging, automatic screen lock), patch management and updates
   - Cover: OS function layer diagram (hardware → OS → applications → user), desktop OS market share comparison, GUI vs CLI comparison, virtualization architecture (Type 1 vs Type 2 hypervisor)

5. **"Application Software & Productivity"** — Software categories: system software (OS, utilities, drivers) vs application software (programs users interact with). Application types: productivity (word processing, spreadsheets, presentations, databases), communication (email, messaging, video conferencing), creative (photo/video editing, graphic design, music production), business (ERP, CRM, accounting), specialized (EHR, PACS, coding software — 3M, Optum, medical billing). Productivity suites: Microsoft 365 (Word, Excel, PowerPoint, Outlook, Teams, Access, OneNote, SharePoint — cloud-based subscription, formerly Office 365), Google Workspace (Docs, Sheets, Slides, Gmail, Meet, Drive — web-based, collaboration-first), Apple iWork (Pages, Numbers, Keynote — free on Apple devices). Microsoft 365 deep dive (relevant to course series): Word (document processing — formatting, styles, templates, mail merge, track changes, comments), Excel (spreadsheets — formulas, functions, charts, PivotTables, data analysis — covered in detail in Excel 365 book), PowerPoint (presentations — slides, themes, animations, speaker notes), Outlook (email, calendar, contacts, tasks — enterprise communication), Teams (collaboration hub — chat, video meetings, channels, file sharing, integration with other M365 apps), Access (desktop database — tables, queries, forms, reports), SharePoint (intranet, document management, workflows). Software licensing: proprietary (paid license — perpetual or subscription), open-source (free to use/modify — LibreOffice, GIMP, Audacity), freeware (free but not open source), shareware/trial, SaaS (Software as a Service — web-based, subscription). Software installation: traditional (download/install .exe or .msi), app store (curated marketplace), web-based (no install — runs in browser), enterprise deployment (SCCM, Intune — IT department pushes software to computers). Healthcare software: EHR systems (Epic, Oracle Health/Cerner, MEDITECH, Allscripts), coding software (3M, Optum/EncoderPro, TruCode), CDI software, revenue cycle management, health analytics platforms (Tableau, Power BI, SAS), PACS (picture archiving and communication — radiology images)
   - Cover: Software category hierarchy, Microsoft 365 app ecosystem diagram, licensing model comparison, healthcare software categories grid

### Unit 2: Internet, Networks & Communication (L6-10)
6. **"The Internet: Architecture & How It Works"** — Internet history: ARPANET (1969, Department of Defense, 4 nodes), TCP/IP adoption (1983, Vinton Cerf & Bob Kahn), World Wide Web (1991, Tim Berners-Lee at CERN — HTML + HTTP + URL), commercialization (1990s, browsers — Mosaic, Netscape, Internet Explorer), broadband era (2000s), mobile internet (2010s), current state (~5 billion users worldwide). How the internet works: packet switching (data broken into packets, sent independently, reassembled at destination), TCP/IP protocol suite (Application layer — HTTP, SMTP, FTP, DNS; Transport layer — TCP reliable/UDP fast; Internet layer — IP addressing, routing; Network Access layer — Ethernet, Wi-Fi). IP addressing: IPv4 (32-bit, 4.3 billion addresses, exhausted — dotted decimal notation 192.168.1.1), IPv6 (128-bit, essentially unlimited, hexadecimal notation 2001:0db8::1), public vs private IP addresses (NAT — Network Address Translation), DHCP (Dynamic Host Configuration Protocol — automatic IP assignment), static vs dynamic IPs. DNS (Domain Name System): translates domain names (google.com) to IP addresses, hierarchical — root servers → TLD servers (.com, .org, .edu, .gov) → authoritative name servers, DNS cache, DNS poisoning attacks. Internet infrastructure: ISPs (Internet Service Providers — tiers: Tier 1 backbone, Tier 2 regional, Tier 3 local), connection types (fiber optic — fastest, cable, DSL, satellite, cellular — 4G LTE, 5G), bandwidth vs latency (bandwidth = capacity, latency = delay), upload vs download speed. Internet governance: ICANN (domain names), IETF (technical standards — RFCs), W3C (web standards)
   - Cover: Internet architecture diagram (client → ISP → backbone → server), TCP/IP 4-layer model, IPv4 vs IPv6 comparison, DNS resolution process flowchart

7. **"The World Wide Web & Web Technologies"** — Web vs Internet: internet = infrastructure (physical network), web = service on the internet (HTTP + HTML + URLs). How the web works: client (browser) sends HTTP request → web server processes request → returns HTTP response (HTML, CSS, JS, images). URLs: protocol (https://), domain (www.example.com), path (/page/subpage), query string (?key=value). HTTP/HTTPS: HTTP methods (GET = retrieve, POST = submit data, PUT = update, DELETE = remove), status codes (200 OK, 301 redirect, 403 forbidden, 404 not found, 500 server error), HTTPS = HTTP + TLS/SSL encryption (green padlock, certificate). Web browsers: Chrome, Firefox, Safari, Edge — rendering engines (Blink, Gecko, WebKit), tabs, bookmarks, extensions, private/incognito mode, cookie management. HTML/CSS/JavaScript: HTML (structure — headings, paragraphs, lists, links, images, forms, tables, semantic tags), CSS (presentation — colors, fonts, layouts, responsive design — media queries, frameworks like Bootstrap), JavaScript (interactivity — form validation, dynamic content, AJAX, frameworks — React, Angular, Vue). Web 1.0 → Web 2.0 → Web 3.0: static pages → user-generated content/social media → semantic web/decentralized. E-commerce: B2C, B2B, C2C, payment processing (PCI DSS compliance), shopping cart, digital wallets. Search engines: how they work (crawling → indexing → ranking), SEO basics, search operators, evaluating search results (sponsored vs organic). Web accessibility: WCAG (Web Content Accessibility Guidelines), Section 508 compliance, screen readers, alt text, keyboard navigation. Healthcare web: patient portals (21st Century Cures Act — information blocking), telehealth platforms, health information websites (evaluating quality — HONcode)
   - Cover: How the web works (client-server request/response), URL anatomy diagram, HTTP status code reference, Web 1.0 → 2.0 → 3.0 evolution

8. **"Computer Networks: Types, Topologies & Protocols"** — Network definition: two or more devices connected to share resources and communicate. Network types by size: PAN (Personal Area Network — Bluetooth devices, ~10m), LAN (Local Area Network — single building/campus, Ethernet/Wi-Fi, fastest), MAN (Metropolitan Area Network — city-wide, fiber backbone), WAN (Wide Area Network — spans large geographic area, the internet is the largest WAN), VPN (Virtual Private Network — encrypted tunnel over public internet, remote access for employees). Network topologies: bus (single cable, old), star (central hub/switch, most common in modern LANs), ring (data passes in a circle), mesh (every device connected to every other — full mesh expensive, partial mesh practical, used in IoT/wireless), hybrid (combination). Network architectures: client-server (centralized — clients request, server provides, enterprise standard, Active Directory), peer-to-peer (P2P — all devices equal, file sharing, small networks), cloud-based (resources hosted off-premises). Network hardware: NIC (network interface card — wired or wireless), switch (connects devices in LAN, forwards frames using MAC addresses), router (connects networks, forwards packets using IP addresses, NAT, firewall), access point (wireless — provides Wi-Fi), modem (modulator-demodulator — converts digital to analog for ISP connection), firewall (hardware or software — filters traffic based on rules). Network protocols: Ethernet (IEEE 802.3, wired LAN, Cat5e/Cat6/Cat6a cabling, RJ-45 connector, speeds — 100 Mbps to 10 Gbps), Wi-Fi (IEEE 802.11 — a/b/g/n/ac/ax/be, 2.4 GHz vs 5 GHz vs 6 GHz, WPA3 security), Bluetooth (short-range wireless, pairing), cellular (4G LTE, 5G). Healthcare networking: hospital network infrastructure (wired backbone + Wi-Fi for mobility, medical device networks, segmentation for security, guest networks), HIPAA network requirements (encryption in transit, access controls, network monitoring, intrusion detection), telemedicine bandwidth requirements
   - Cover: Network types by size diagram (PAN → WAN), topology comparison grid, network hardware identification, Wi-Fi standard evolution table

9. **"Network Communication & Data Transmission"** — How data travels: analog vs digital signals, modulation/demodulation, bandwidth (amount of data per second — bps, Kbps, Mbps, Gbps), throughput (actual speed achieved vs theoretical maximum), latency (delay — measured in ms, important for telehealth video). Transmission media: wired — twisted pair (Cat5e/Cat6/Cat6a, UTP vs STP, max 100m runs), coaxial cable (legacy, cable TV/internet), fiber optic (single-mode vs multi-mode, light pulses, fastest, immune to electromagnetic interference, long distance, backbone infrastructure); wireless — radio waves (Wi-Fi, cellular, Bluetooth), infrared (legacy remote controls), microwave (point-to-point, satellite). OSI Model (7 layers): Physical (cables, signals, bits), Data Link (MAC addresses, frames, switches, Ethernet), Network (IP addresses, packets, routers, routing), Transport (TCP/UDP, segments, ports, reliable delivery), Session (establishing/maintaining connections), Presentation (encryption, compression, data format conversion), Application (HTTP, SMTP, FTP, DNS — protocols users interact with). OSI vs TCP/IP model: TCP/IP combines top 3 OSI layers into Application, bottom 2 into Network Access. Ports: logical endpoints for communication (HTTP = 80, HTTPS = 443, FTP = 21, SSH = 22, SMTP = 25, DNS = 53, RDP = 3389), well-known ports (0-1023), registered ports (1024-49151), dynamic ports (49152-65535). Network administration: IP configuration (ipconfig/ifconfig), ping (test connectivity), traceroute/tracert (trace packet path), nslookup (DNS query), netstat (active connections). Healthcare data transmission: HL7 messaging (ADT, orders, results — between EHR systems), DICOM (medical imaging transmission), FHIR API (modern healthcare interoperability — RESTful), secure transmission requirements (TLS 1.2+, VPN for remote access, encrypted email for PHI)
   - Cover: OSI 7-layer model with examples at each layer, fiber optic vs copper comparison, common port numbers reference card, healthcare data transmission protocols (HL7/DICOM/FHIR)

10. **"Wireless Technologies & Mobile Computing"** — Wi-Fi deep dive: IEEE 802.11 standards evolution (802.11b = 11 Mbps → 802.11g = 54 Mbps → 802.11n/Wi-Fi 4 = 600 Mbps → 802.11ac/Wi-Fi 5 = 3.5 Gbps → 802.11ax/Wi-Fi 6/6E = 9.6 Gbps → 802.11be/Wi-Fi 7 = 46 Gbps), frequency bands (2.4 GHz = longer range, more interference vs 5 GHz = faster, shorter range vs 6 GHz = fastest, least congestion), SSID (network name), authentication (WPA2/WPA3 personal vs enterprise — RADIUS server). Cellular technology: generations (1G analog → 2G digital/SMS → 3G mobile data → 4G LTE broadband → 5G ultra-fast/low-latency), 5G types (low-band = wide coverage, mid-band = balance, mmWave = ultra-fast but short range), SIM cards (physical, eSIM), hotspot/tethering. Bluetooth: versions (5.0-5.4), profiles (A2DP audio, HID keyboard/mouse, SPP serial), pairing process, BLE (Bluetooth Low Energy — medical devices, beacons, wearables). NFC (Near Field Communication): contactless payment (Apple Pay, Google Pay), range ~4cm, tap-to-pair. Mobile operating systems: iOS (Apple — closed ecosystem, consistent UX, App Store review, regular updates, strong privacy), Android (Google — open-source base, customizable, Play Store, fragmentation across manufacturers). Mobile device management (MDM): enterprise control of mobile devices (Intune, JAMF, VMware Workspace ONE), features — remote wipe, policy enforcement, app management, encryption, containerization (separate work/personal data). BYOD (Bring Your Own Device): policy considerations, security risks, employee privacy vs employer security, acceptable use policies. Mobile in healthcare: clinical communication (secure messaging — TigerConnect, Vocera), EHR mobile apps (Epic Haiku/Canto, Cerner PowerChart Touch), mHealth (patient-facing apps — medication reminders, symptom tracking, remote monitoring), telehealth (video visits, remote patient monitoring — RPM), FDA regulation of medical apps (SaMD — Software as a Medical Device). Mobile security: screen lock (PIN, pattern, biometric — fingerprint, face recognition), encryption (full device encryption — enabled by default on modern iOS/Android), app permissions (camera, location, contacts, microphone — principle of least privilege), public Wi-Fi risks (man-in-the-middle attacks, use VPN), lost/stolen device (Find My iPhone/Find My Device, remote lock/wipe)
    - Cover: Wi-Fi standards evolution timeline, cellular generation comparison (1G-5G), mobile device management feature grid, healthcare mobile app categories

### Unit 3: Cybersecurity & Digital Ethics (L11-15)
11. **"Cybersecurity Fundamentals"** — CIA triad: Confidentiality (only authorized people access data), Integrity (data is accurate and unaltered), Availability (systems and data are accessible when needed). AAA framework: Authentication (verify identity — who are you?), Authorization (verify permissions — what can you access?), Accounting/Auditing (track activity — what did you do?). Threat landscape: threat (potential danger), vulnerability (weakness that can be exploited), exploit (method of attack), risk (probability × impact). Threat actors: script kiddies (unskilled, use existing tools), hacktivists (politically motivated), cybercriminals (financially motivated — organized crime), nation-state actors (government-sponsored, APT — Advanced Persistent Threats), insider threats (employees, contractors — malicious or negligent). Attack types: malware (virus — attaches to programs, worm — self-replicating/spreads automatically, trojan — disguised as legitimate, ransomware — encrypts files/demands payment — WannaCry, Colonial Pipeline, healthcare frequent target, spyware — monitors activity, adware — unwanted ads, rootkit — hides deep in OS, keylogger — records keystrokes), phishing (email deception — spear phishing = targeted, whaling = targeting executives, vishing = voice, smishing = SMS), social engineering (manipulating people — pretexting, baiting, tailgating, quid pro quo), man-in-the-middle (intercepting communication), denial of service (DoS/DDoS — overwhelming systems), SQL injection (inserting malicious database commands), cross-site scripting (XSS — injecting scripts into web pages), brute force (trying all password combinations), credential stuffing (using leaked passwords across sites), zero-day (exploiting unknown vulnerability — no patch available)
    - Cover: CIA triad diagram, attack type taxonomy tree, malware type comparison grid, phishing red flags checklist

12. **"Cybersecurity Defenses & Best Practices"** — Defense in depth: multiple layers of security (physical → network → host → application → data → user). Physical security: locks, badges, security cameras, mantraps (two-door vestibule), biometrics, clean desk policy. Network security: firewalls (packet filtering, stateful inspection, next-gen — NGFW with deep packet inspection/IPS), IDS/IPS (Intrusion Detection/Prevention System — signature-based vs anomaly-based), DMZ (demilitarized zone — public-facing servers separated from internal network), network segmentation (VLANs — isolating sensitive systems), VPN (encrypted remote access). Endpoint security: antivirus/anti-malware (signature + heuristic + behavioral detection), EDR (Endpoint Detection and Response — advanced threat detection), patch management (keeping OS and applications updated — many breaches exploit known vulnerabilities), host-based firewall, full disk encryption (BitLocker for Windows, FileVault for Mac), application whitelisting. Authentication security: passwords (strong: 12+ characters, mix of upper/lower/numbers/symbols, unique per account), MFA/2FA (multi-factor authentication — something you know + something you have + something you are: password + authenticator app/SMS code + fingerprint), SSO (single sign-on — one login for multiple systems, reduces password fatigue), passwordless (FIDO2, passkeys, biometric). Data security: encryption (at rest — stored data, in transit — data being transmitted, end-to-end), AES (Advanced Encryption Standard — symmetric, 128/256-bit), RSA (asymmetric — public/private key pair), hashing (one-way function — SHA-256, used for password storage, digital signatures), data loss prevention (DLP — monitoring and preventing unauthorized data exfiltration), data classification (public, internal, confidential, restricted). Backup strategy: 3-2-1 rule (3 copies, 2 different media types, 1 offsite/cloud), RTO (Recovery Time Objective — how fast you need to recover), RPO (Recovery Point Objective — how much data loss is acceptable), backup types (full, incremental, differential), disaster recovery plan
    - Cover: Defense-in-depth layers diagram, MFA factors illustration, encryption types comparison (symmetric vs asymmetric), 3-2-1 backup rule visualization

13. **"Healthcare Cybersecurity & HIPAA Security"** — Why healthcare is a top target: healthcare data is most valuable on black market ($250-$1000 per record vs $5-$50 for credit card), large attack surface (EHR, medical devices, legacy systems), 24/7 operations (can't easily take systems down for patching), life-or-death urgency (ransomware leverage — hospitals may pay to restore patient care). Healthcare breach statistics: average cost $10.93 million per breach (highest of any industry, IBM 2023), 725+ breaches of 500+ records reported to HHS in 2023, primary causes — hacking (79%), unauthorized access (15%), theft (3%), loss (2%), improper disposal (1%). HIPAA Security Rule: applies to ePHI (electronic protected health information), requires safeguards — Administrative (risk analysis, workforce training, incident procedures, contingency planning, BAAs), Physical (facility access controls, workstation use/security, device and media controls), Technical (access controls — unique user ID, emergency access, automatic logoff, encryption; audit controls — log all access to ePHI; integrity controls — mechanism to confirm ePHI not altered; transmission security — encryption for ePHI in transit; person or entity authentication). Risk analysis requirement: HIPAA requires annual risk assessment (identify threats, vulnerabilities, likelihood, impact, current controls, risk level, remediation plan), OCR (Office for Civil Rights) enforces — lack of risk analysis is #1 finding in investigations. Security incident response: detection (SIEM — Security Information and Event Management, anomaly detection), containment (isolate affected systems), eradication (remove threat), recovery (restore from backup, verify integrity), lessons learned (update policies, re-train). Medical device security: IoMT (Internet of Medical Things) — connected infusion pumps, ventilators, imaging equipment, pacemakers — many run legacy OS (Windows XP), difficult to patch, network segmentation critical, FDA cybersecurity guidance for manufacturers
    - Cover: Healthcare breach cost comparison across industries, HIPAA Security Rule safeguard categories with examples, risk analysis process flowchart, medical device security challenges diagram

14. **"Digital Ethics, Privacy & Responsible Use"** — Digital ethics frameworks: utilitarianism (greatest good for greatest number), deontology (duty-based — certain actions are inherently right/wrong regardless of outcome), virtue ethics (character-based — what would a virtuous person do?). Key ethical issues in technology: privacy (right to control personal information — collection, use, sharing, retention), surveillance (government and corporate monitoring, facial recognition, location tracking), algorithmic bias (AI systems reflecting/amplifying human biases — racial bias in healthcare algorithms, hiring algorithms, criminal justice), digital divide (unequal access to technology based on income, geography, age, disability — rural broadband gaps, impact on telehealth access), intellectual property (copyright, patents, trademarks, fair use, Creative Commons, software piracy, DRM), misinformation/disinformation (false information — unintentional vs intentional, deepfakes, health misinformation — anti-vax, miracle cures), automation and jobs (AI replacing human tasks, reskilling needs, impact on HIM — automated coding, CDI AI). Privacy laws: HIPAA (healthcare — PHI, TPO, minimum necessary, individual rights, breach notification), FERPA (education), COPPA (children under 13), GDPR (European Union — consent, right to erasure, data portability, DPO, fines up to 4% global revenue), CCPA/CPRA (California — consumer rights, do not sell, right to delete), state privacy laws (emerging patchwork). Digital footprint: active (intentionally posted — social media, comments, uploads) vs passive (collected without active participation — cookies, browsing history, location data, metadata), persistence (difficult to fully delete), implications for employment/reputation. Responsible use: acceptable use policies (AUP), social media policies (especially for healthcare workers — patient privacy on social media, HIPAA violations from selfies/posts), screen time and digital wellness, cyberbullying prevention
    - Cover: Ethics framework comparison table, privacy law comparison grid (HIPAA/GDPR/CCPA), digital footprint types, algorithmic bias examples in healthcare

15. **"Information Security Governance & Compliance"** — Information security governance: policies, procedures, standards, guidelines — hierarchy. Policy types: organizational security policy (high-level direction), acceptable use policy (AUP — rules for using company resources), password policy (complexity, rotation, history), email/internet policy, remote work/BYOD policy, incident response policy, data classification policy, clean desk/clear screen policy. Compliance frameworks: HIPAA (healthcare — covered entities, business associates, PHI, ePHI), PCI DSS (Payment Card Industry Data Security Standard — 12 requirements for handling credit card data), SOC 2 (Service Organization Control — trust service criteria: security, availability, processing integrity, confidentiality, privacy, relevant for cloud providers), NIST Cybersecurity Framework (5 functions: Identify, Protect, Detect, Respond, Recover — widely adopted, voluntary but recommended by HHS for healthcare), HITRUST CSF (Health Information Trust Alliance Common Security Framework — combines HIPAA, NIST, ISO 27001, PCI into one healthcare framework, certification process). Security awareness training: annual requirement for HIPAA, topics — phishing recognition, password hygiene, clean desk, social engineering, incident reporting, removable media, mobile device security, social media risks. Business continuity and disaster recovery: BCP (business continuity plan — maintaining operations during disruption), DRP (disaster recovery plan — restoring IT systems after disaster), BIA (business impact analysis — identify critical systems and RTO/RPO for each), tabletop exercises (simulated scenarios), hot/warm/cold sites (standby facilities — hot = ready immediately, warm = ready in hours, cold = ready in days). Security audits: internal audit (self-assessment), external audit (third-party, compliance verification), penetration testing (authorized simulated attack — find vulnerabilities before attackers do), vulnerability scanning (automated tool — Nessus, Qualys)
    - Cover: Policy hierarchy pyramid, NIST Cybersecurity Framework 5 functions, compliance framework comparison (HIPAA/PCI/SOC 2/HITRUST), BC/DR site types comparison

### Unit 4: Data, Databases & Programming (L16-19)
16. **"Database Fundamentals"** — What is a database: organized collection of structured data, managed by a DBMS (Database Management System). Why databases matter: eliminate data redundancy, maintain data integrity, enable efficient retrieval, support concurrent access, enforce security. Database models: flat file (single table, spreadsheet-like — limited), hierarchical (tree structure, parent-child — legacy IMS), network (many-to-many relationships, complex), relational (tables with relationships — dominant model since 1970s, E.F. Codd at IBM), object-oriented (objects with attributes and methods), NoSQL (non-relational — document stores like MongoDB, key-value like Redis, column-family like Cassandra, graph databases like Neo4j — big data, unstructured data, scalability). Relational database concepts: table (relation — rows and columns), record/row (tuple — one entity instance), field/column (attribute — one data element), primary key (unique identifier for each record — patient MRN, SSN, auto-increment ID), foreign key (field that references primary key in another table — creates relationship), composite key (multiple fields forming unique identifier). Relationships: one-to-one (patient → single SSN), one-to-many (physician → many patients, most common), many-to-many (patients ↔ medications, requires junction/bridge table). Database design: entity-relationship diagram (ERD — entities, attributes, relationships, cardinality notation), normalization (reducing redundancy — 1NF: atomic values, no repeating groups; 2NF: 1NF + no partial dependencies; 3NF: 2NF + no transitive dependencies), denormalization (intentionally adding redundancy for read performance — data warehouses). Popular RDBMS: Microsoft SQL Server, Oracle Database, MySQL (open-source), PostgreSQL (open-source), Microsoft Access (desktop). Healthcare databases: EHR database (patient demographics, encounters, diagnoses, medications, lab results), master patient index (MPI — central patient identification), claims databases, clinical registries, data warehouses (aggregated data for analytics/reporting)
    - Cover: Database model evolution timeline, relational database anatomy (table/record/field/key), ERD example with healthcare entities, normalization progression (unnormalized → 3NF)

17. **"SQL & Data Querying"** — SQL (Structured Query Language): standard language for relational databases, ANSI standard, declarative (tell the database WHAT you want, not HOW to get it). SQL categories: DDL (Data Definition Language — CREATE, ALTER, DROP), DML (Data Manipulation Language — SELECT, INSERT, UPDATE, DELETE), DCL (Data Control Language — GRANT, REVOKE). SELECT statement anatomy: SELECT columns FROM table WHERE condition ORDER BY column ASC/DESC; wildcards (SELECT * = all columns). Filtering: WHERE clause (= equals, <> not equal, > < >= <=, BETWEEN, LIKE with % and _ wildcards, IN (list), IS NULL / IS NOT NULL), AND/OR/NOT logical operators. Aggregate functions: COUNT (number of rows), SUM (total), AVG (average), MIN (minimum), MAX (maximum), GROUP BY (group results for aggregation), HAVING (filter groups — like WHERE but for aggregated data). Joins: INNER JOIN (only matching rows from both tables), LEFT JOIN (all rows from left table + matching from right), RIGHT JOIN (all rows from right table + matching from left), FULL OUTER JOIN (all rows from both), CROSS JOIN (Cartesian product — every combination). Subqueries: query nested inside another query (WHERE field IN (SELECT...)). INSERT: adding new records (INSERT INTO table (columns) VALUES (values)). UPDATE: modifying existing records (UPDATE table SET column = value WHERE condition — always use WHERE!). DELETE: removing records (DELETE FROM table WHERE condition — always use WHERE!). Healthcare SQL examples: query patient demographics by diagnosis, count admissions by month, calculate average length of stay, find patients with specific medication, join diagnosis and procedure tables. Views: saved queries that act as virtual tables (CREATE VIEW), simplify complex queries, provide security (limit what users see). Stored procedures: pre-compiled SQL programs, reusable, parameters, security benefits
    - Cover: SQL statement anatomy diagram, JOIN types Venn diagrams, aggregate function examples with healthcare data, query building progression (simple → complex)

18. **"Programming & Computational Thinking"** — What is programming: writing instructions (code) that a computer can execute to perform tasks. Why HIM professionals should understand programming: automation (batch processing, report generation), data analysis (Python, R for analytics), EHR customization (rules, alerts, templates), career advancement (health informatics, data science). Programming concepts: variables (named storage — data types: integer, float/decimal, string, boolean, date), operators (arithmetic: + - * / %, comparison: == != > < >= <=, logical: AND OR NOT), control structures (sequential — step by step, selection/conditional — if/else/switch: "if diagnosis is cancer, add to registry", iteration/loops — for/while/do-while: "for each patient in discharge list, check record completeness"), functions/methods (reusable blocks of code, parameters, return values — "calculateLOS(admitDate, dischargeDate)"), arrays/lists (ordered collection of items — list of diagnosis codes), dictionaries/objects (key-value pairs — {"MRN": "12345", "Name": "Smith, John", "DOB": "1985-03-15"}). Programming paradigms: procedural (step-by-step instructions — C, Pascal), object-oriented (objects with properties and methods — Java, C#, Python), functional (functions as first-class citizens, immutable data — Haskell, aspects of Python/JavaScript), scripting (interpreted, automation — Python, PowerShell, JavaScript, VBA). Common languages and their uses: Python (data analysis, AI/ML, automation, scripting — most popular for beginners, healthcare analytics), JavaScript (web development — front-end and back-end with Node.js), SQL (databases — already covered, essential for HIM), VBA (Visual Basic for Applications — Excel/Access automation, macros), R (statistical computing, data visualization, bioinformatics), Java (enterprise applications, Android), C# (Microsoft ecosystem, .NET, healthcare applications), HTML/CSS (web content — not programming languages but essential). Computational thinking: decomposition (break complex problems into smaller parts), pattern recognition (identify similarities/trends in data), abstraction (focus on important information, ignore irrelevant details), algorithm design (step-by-step solution — pseudocode, flowcharts)
    - Cover: Programming concept building blocks (variables → operators → control structures → functions), language popularity/use case comparison, computational thinking 4 pillars, flowchart symbols reference

19. **"Data Analytics & Business Intelligence"** — Data analytics defined: process of examining data to find patterns, draw conclusions, and support decision-making. Analytics maturity model: descriptive (what happened? — reports, dashboards, KPIs), diagnostic (why did it happen? — drill-down, root cause analysis, correlation), predictive (what will happen? — statistical models, machine learning, forecasting), prescriptive (what should we do? — optimization, simulation, decision support, AI recommendations). Data warehouse: centralized repository of integrated data from multiple sources, designed for query and analysis (not transactions), ETL process (Extract from source systems → Transform/clean/standardize → Load into warehouse), dimensional modeling (fact tables + dimension tables, star schema, snowflake schema), data mart (subset of warehouse for specific department — coding, clinical, financial). Business intelligence (BI) tools: dashboards (visual display of KPIs — real-time or near-real-time), reports (structured presentation of data — scheduled or ad-hoc), scorecards (performance against targets — RAG status: Red/Amber/Green), ad-hoc queries (user-driven exploration). Popular BI platforms: Microsoft Power BI (M365 integration, DAX, Power Query), Tableau (visual analytics, drag-and-drop), Qlik (associative analytics engine), SAS (advanced analytics, statistical), Excel with PivotTables and Power Pivot (most accessible entry point). Data visualization: choosing the right chart (bar = comparison, line = trend over time, pie = composition (use sparingly!), scatter = relationship/correlation, histogram = distribution, heat map = intensity, geographic/map = location-based, Gantt = timeline/project), design principles (minimize chartjunk, maximize data-ink ratio — Tufte, consistent colors, clear labels, accessible color palettes). Healthcare analytics: clinical analytics (outcomes, quality measures, readmission prediction, sepsis early warning), financial analytics (revenue cycle, cost per case, payer mix, denial trends), operational analytics (throughput, staffing, bed management, OR utilization), population health (risk stratification, care gaps, chronic disease management). HIM role in analytics: data quality stewardship (garbage in = garbage out), coding accuracy drives analytics accuracy, CDI impact on severity data, MPI integrity, data governance
    - Cover: Analytics maturity model pyramid, ETL/data warehouse architecture, chart selection guide matrix, healthcare analytics categories with examples

### Unit 5: Emerging Technologies (L20-23)
20. **"Cloud Computing"** — Cloud computing defined (NIST): on-demand network access to shared pool of configurable computing resources, rapidly provisioned with minimal management effort. Essential characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity (scale up/down automatically), measured service (pay for what you use). Service models: IaaS (Infrastructure as a Service — virtual machines, storage, networking — YOU manage: OS, middleware, apps, data — examples: AWS EC2, Azure Virtual Machines, Google Compute Engine), PaaS (Platform as a Service — development platform, runtime environment — YOU manage: apps, data — examples: Azure App Service, Google App Engine, Heroku), SaaS (Software as a Service — complete application delivered via browser — YOU manage: just data/configuration — examples: Microsoft 365, Salesforce, Epic in cloud, Google Workspace), FaaS/Serverless (Function as a Service — event-driven code execution, no server management — AWS Lambda, Azure Functions). Deployment models: public cloud (shared infrastructure, multi-tenant — AWS, Azure, GCP — cost-effective, scalable), private cloud (dedicated infrastructure, single-tenant — VMware, OpenStack — more control, HIPAA-friendly), hybrid cloud (combination — sensitive data on-premises/private, scalable workloads on public — most common in healthcare), multi-cloud (using multiple cloud providers — avoid vendor lock-in, best-of-breed services). Major cloud providers: AWS (Amazon Web Services — largest market share, 200+ services), Microsoft Azure (#2, strong M365/Active Directory integration, popular in healthcare/enterprise), Google Cloud Platform (GCP — strong in AI/ML, data analytics, Kubernetes). Cloud in healthcare: HIPAA-compliant cloud (AWS GovCloud, Azure Government, BAA requirements, encryption at rest and in transit, access controls, audit logging), EHR hosting (Epic Nebula/Hyperdrive, Oracle Health cloud), medical imaging (cloud PACS), disaster recovery, telehealth infrastructure, AI/ML workloads (training models on PHI requires HIPAA controls). Cloud security: shared responsibility model (cloud provider secures infrastructure, customer secures data/configuration/access), identity and access management (IAM — roles, policies, least privilege), encryption (KMS — Key Management Service), compliance certifications (HITRUST, SOC 2, FedRAMP), cloud misconfigurations (exposed S3 buckets, open ports — leading cause of cloud breaches)
    - Cover: Service model comparison (IaaS/PaaS/SaaS) responsibility stack, deployment model comparison, major cloud providers overview, shared responsibility model diagram

21. **"Artificial Intelligence & Machine Learning"** — AI defined: computer systems performing tasks that typically require human intelligence — perception, reasoning, learning, decision-making, natural language understanding. AI timeline: Turing Test (1950), Dartmouth Conference "birth of AI" (1956), expert systems (1970s-80s), AI winters (funding cuts due to unmet expectations), machine learning resurgence (2000s), deep learning revolution (2010s — ImageNet 2012, AlphaGo 2016), generative AI explosion (2022+ — ChatGPT, GPT-4, Claude, Gemini, DALL-E, Midjourney). Types of AI: narrow/weak AI (specialized single task — chess, image recognition, language translation — ALL current AI), general/strong AI (human-level intelligence across all domains — hypothetical, does not exist), superintelligence (beyond human — theoretical). Machine learning: subset of AI where systems learn from data without explicit programming. ML types: supervised learning (labeled training data — classification: spam/not-spam, malignant/benign; regression: predicting numerical values — length of stay, cost), unsupervised learning (no labels — clustering: patient segmentation, grouping similar conditions; dimensionality reduction), reinforcement learning (learn through trial and reward — robotics, game playing, treatment optimization). Deep learning: neural networks with many layers, inspired by brain neurons, excels at: image recognition (radiology AI — detecting tumors, fractures), natural language processing (NLP — clinical note understanding, voice-to-text), speech recognition, generative tasks. Key concepts: training data (garbage in = garbage out), overfitting (memorizes training data, fails on new data), bias (training data biases → biased predictions — racial, gender, socioeconomic), explainability (black box problem — can't always explain WHY AI made a decision, critical in healthcare). AI in healthcare: clinical decision support (diagnosis assistance, treatment recommendations, drug interaction checking), medical imaging (radiology AI — FDA-approved algorithms for mammography, CT, retinal scans), NLP (extracting information from clinical notes, automated coding, CDI, sentiment analysis of patient feedback), predictive models (sepsis prediction, readmission risk, patient deterioration — early warning scores), robotic surgery (da Vinci system — surgeon-controlled, not autonomous), drug discovery (molecule screening, clinical trial matching), administrative AI (prior authorization, claims processing, scheduling optimization), generative AI for healthcare (ambient clinical documentation — DAX Copilot, clinical summarization). AI ethics and governance: FDA regulation of AI/ML as medical devices (SaMD — Software as a Medical Device, predetermined change control plan), algorithmic bias in healthcare (pulse oximetry less accurate on darker skin, algorithms underestimating Black patients' needs), AI transparency and explainability, patient consent for AI-assisted diagnosis, liability (who is responsible when AI makes wrong diagnosis — physician, hospital, AI developer?), human oversight (AI as decision support, not decision maker)
    - Cover: AI/ML/deep learning nested diagram, supervised vs unsupervised learning comparison, healthcare AI applications grid, AI ethics considerations framework

22. **"Internet of Things (IoT) & Smart Systems"** — IoT defined: network of physical objects ("things") embedded with sensors, software, and connectivity to collect and exchange data. IoT architecture: sensors/devices (data collection) → connectivity (Wi-Fi, Bluetooth, Zigbee, cellular, LoRaWAN) → edge computing (local processing, reduce latency) → cloud platform (storage, analytics, management) → application (dashboard, alerts, automation). IoT scale: estimated 15+ billion connected devices (2023), projected 30+ billion by 2030. Smart home: thermostats (Nest, Ecobee), lighting (Philips Hue, smart switches), security (Ring, Arlo cameras, smart locks), voice assistants (Alexa, Google Home, Siri — privacy concerns), smart appliances, home energy management. Smart cities: traffic management (adaptive signals, connected vehicles), waste management (fill-level sensors), street lighting (adaptive), environmental monitoring (air quality, noise), public safety (surveillance, gunshot detection). Industrial IoT (IIoT): manufacturing (predictive maintenance, quality monitoring), agriculture (precision farming, soil sensors, drone monitoring), supply chain (asset tracking, cold chain monitoring), energy (smart grid, renewable energy management). IoMT (Internet of Medical Things): patient monitoring — wearables (Apple Watch ECG/fall detection, continuous glucose monitors — Dexcom, blood pressure monitors, pulse oximeters), implantables (pacemakers, insulin pumps, cochlear implants), hospital — smart beds (pressure monitoring, fall prevention), infusion pumps (networked — dose tracking, drug library, alerts), patient tracking (RFID wristbands, RTLS — Real-Time Location System for equipment/patients/staff), environmental monitoring (temperature for medication storage, humidity for sterile supply, air pressure for isolation rooms), remote patient monitoring (RPM — chronic disease management at home, post-discharge monitoring, elderly care, CMS reimbursement for RPM). IoT security challenges: massive attack surface, many devices lack security features (no encryption, default passwords, can't be patched), DDoS attacks from botnets (Mirai botnet used IoT cameras/DVRs), patient safety risks (hacked infusion pump could deliver wrong dose, compromised pacemaker), FDA cybersecurity guidance for connected medical devices, network segmentation (isolate IoT devices on separate VLANs)
    - Cover: IoT architecture layers diagram, IoMT device categories in healthcare, smart hospital concept illustration, IoT security challenge matrix

23. **"Emerging & Future Technologies"** — Blockchain: distributed ledger technology, decentralized (no single point of control/failure), immutable (once recorded, can't be altered), consensus mechanisms (proof of work, proof of stake), smart contracts (self-executing when conditions met), cryptocurrency (Bitcoin, Ethereum), healthcare applications (patient identity verification, clinical trial data integrity, drug supply chain tracking, consent management, health data exchange — patient-controlled), limitations (scalability, energy consumption, complexity, regulatory uncertainty). Extended Reality (XR): Virtual Reality (VR — fully immersive digital environment, headsets — Meta Quest, Apple Vision Pro, healthcare: surgical training, pain management, phobia therapy, anatomy education), Augmented Reality (AR — digital overlay on real world, healthcare: surgical navigation, vein finders, Google Glass for remote consultation, anatomy visualization), Mixed Reality (MR — digital objects interact with real world). 3D printing/additive manufacturing: custom prosthetics, surgical planning models (patient-specific anatomy), bioprinting (tissue/organ printing — research stage), dental applications (crowns, aligners), pharmaceutical (custom-dose medications). Quantum computing: qubits (superposition — 0 and 1 simultaneously, entanglement), exponential processing power for specific problems (cryptography, drug molecule simulation, optimization, protein folding), NOT a replacement for classical computers, current state (NISQ era — Noisy Intermediate-Scale Quantum), quantum threat to encryption (Shor's algorithm could break RSA — post-quantum cryptography being developed). Robotics in healthcare: surgical robots (da Vinci, ROSA), pharmacy robots (automated dispensing — Omnicell, BD Pyxis), disinfection robots (UV-C), telepresence robots (remote physician rounding), rehabilitation robots (exoskeletons), delivery robots (supplies, medications, specimens). Edge computing: processing data near the source (vs sending everything to cloud), reduces latency, critical for real-time medical monitoring, works with IoT. Digital twins: virtual replica of a physical system, simulation and prediction, healthcare — digital twin of a patient (personalized treatment simulation), hospital operations optimization. 5G impact: ultra-low latency (1ms), high bandwidth, massive device connectivity, enables: remote surgery (tactile internet), real-time HD medical imaging, massive IoT deployment, AR/VR in healthcare
    - Cover: Blockchain concept diagram (distributed ledger), XR spectrum (VR → AR → MR), quantum computing concept (classical bit vs qubit), emerging tech healthcare applications matrix
